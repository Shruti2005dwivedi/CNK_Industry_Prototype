# RAG-Driven Tax & Regulatory Knowledge Assistant

Semantic + keyword search over tax circulars, notifications, and internal audit
archives, with citation-grounded answers generated by an LLM. Built for
VIT Pune, TY-F-09 (AI & DS, Sem 5), Project Area: FinTech / RegTech.

> Every answer is either backed by an inline citation `[Source: document, section, date]`
> pulled from your indexed PDFs, or the system says so — it never invents an answer.

## Architecture

```
PDF (circular/notification)
        │
        ▼
 Ingestion (PyMuPDF + OCR fallback via Tesseract)
        │
        ▼
 Chunking (recursive splitter, clause-aware) + metadata tagging
 (source doc, issuing authority, date, section — regex-based)
        │
        ▼
 Embeddings (sentence-transformers, local & free)
        │
        ▼
 Vector Store (ChromaDB, persisted to disk)
        │
        ├──────────────┐
        ▼              ▼
 Semantic search   BM25 keyword search
        └──────┬───────┘
               ▼
   Reciprocal Rank Fusion (hybrid re-rank)
               ▼
   LLM generation (Groq or Gemini) — answers ONLY from
   retrieved context, cites every claim, or returns
   "not found in indexed sources"
               ▼
   SQLite query history log (auditable trail)
               ▼
        FastAPI JSON response ──► frontend/index.html (chat UI)
```

This mirrors the pgvector/Pinecone design in the original project synopsis,
but swaps in **ChromaDB + local embeddings** for the prototype so the whole
thing runs for free with no API keys required until the actual answer-generation
step (where Groq's free tier is used).

## Tech stack (chosen for a real, zero-cost-to-run student deployment)

| Layer | Choice | Why |
|---|---|---|
| Backend | FastAPI + Uvicorn | async, auto docs at `/docs`, industry standard |
| PDF parsing | PyMuPDF + pytesseract OCR fallback | handles both clean and scanned PDFs |
| Chunking | LangChain `RecursiveCharacterTextSplitter` | preserves clause boundaries |
| Embeddings | `sentence-transformers/all-MiniLM-L6-v2` | free, runs locally, no API key |
| Vector store | ChromaDB (persistent, local) | zero setup, swap for pgvector/Pinecone later without touching the rest of the app |
| Keyword search | `rank_bm25` | catches exact section/circular-number queries |
| Hybrid re-rank | Reciprocal Rank Fusion | standard, cheap, no extra model needed |
| LLM | Groq (Llama 3.3 70B, free tier) or Gemini 1.5 Flash | fast + free tiers, swap via `.env` |
| History / audit log | SQLite | zero setup; swap for Postgres in prod (schema unchanged) |
| Frontend | Single-file HTML/JS chat UI | no build step, deployable as a static file |

## Project structure

```
rag-tax-assistant/
├── app/
│   ├── main.py          # FastAPI app & routes
│   ├── config.py         # settings from .env
│   ├── models.py         # pydantic schemas
│   ├── ingestion.py       # PDF parsing, OCR fallback, chunking, metadata tagging
│   ├── embeddings.py      # sentence-transformers wrapper
│   ├── vectorstore.py     # ChromaDB wrapper
│   ├── bm25_index.py      # keyword index
│   ├── retrieval.py       # hybrid search (RRF)
│   ├── generation.py      # LLM call, citation-grounded prompt
│   └── history.py         # SQLite audit log
├── scripts/ingest_cli.py  # bulk-ingest a folder of PDFs from the terminal
├── data/sample_docs/      # a demo circular (+ script to regenerate its PDF)
├── frontend/index.html    # chat UI
├── tests/                 # unit tests (chunking + BM25, no API keys needed)
├── requirements.txt
└── .env.example
```

## Setup

```bash
git clone <your-repo-url>
cd rag-tax-assistant
python3 -m venv venv && source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Get a **free** Groq API key at https://console.groq.com/keys and paste it into
`.env` as `GROQ_API_KEY`. (Or use Gemini: get a key at https://aistudio.google.com/apikey,
set `LLM_PROVIDER=gemini` and `GEMINI_API_KEY` in `.env`.)

> Note: OCR fallback needs the Tesseract binary installed on your machine
> (`sudo apt install tesseract-ocr` on Ubuntu, or `brew install tesseract` on Mac).
> Not required unless you're ingesting scanned PDFs.

## Run it

**1. Seed the knowledge base with the sample circular:**
```bash
python data/sample_docs/make_sample_pdf.py     # generates sample_circular.pdf
python scripts/ingest_cli.py data/sample_docs
```

**2. Start the API:**
```bash
uvicorn app.main:app --reload --port 8000
```
Interactive API docs: http://localhost:8000/docs

**3. Open the frontend:**
Just open `frontend/index.html` in a browser (it talks to `http://localhost:8000`).

**4. Try a query** (via curl, the docs UI, or the frontend):
```bash
curl -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"query": "Can I claim ITC on a delayed invoice?", "session_id": "demo"}'
```

You should get back an answer citing `CBDT Circular No. 12/2026` — the sample
document already covers exactly this question.

## Running tests

The chunking and BM25 tests run with no API keys and no model downloads:
```bash
python tests/test_chunking.py
python tests/test_bm25_retrieval.py
```

## Deploying (free-tier friendly)

- **Backend**: [Render](https://render.com) or [Railway](https://railway.app) free web
  service — point it at this repo, start command `uvicorn app.main:app --host 0.0.0.0 --port $PORT`,
  set the same env vars from `.env` in their dashboard. Mount a persistent disk for
  `chroma_db/` and `query_history.db` so the index survives restarts.
- **Frontend**: push `frontend/index.html` to GitHub Pages / Netlify / Vercel; update
  `API_BASE` in the file to your deployed backend URL.
- **Docker** (optional, for a one-command deploy anywhere):
  ```dockerfile
  FROM python:3.11-slim
  RUN apt-get update && apt-get install -y tesseract-ocr && rm -rf /var/lib/apt/lists/*
  WORKDIR /app
  COPY requirements.txt .
  RUN pip install --no-cache-dir -r requirements.txt
  COPY . .
  CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
  ```

## Migrating from the prototype stack to the original design doc's stack

| Prototype (this repo) | Production (per synopsis) | Change needed |
|---|---|---|
| ChromaDB (local) | PostgreSQL + pgvector, or Pinecone | rewrite `vectorstore.py` only |
| SQLite | PostgreSQL | swap connection string in `history.py`, same schema |
| sentence-transformers (local) | Gemini/OpenAI embeddings | swap `embeddings.py` to call the API instead |
| Groq/Gemini chat | Gemini/OpenAI via LangChain/LlamaIndex | swap `generation.py`'s call, keep the same prompt |

Every other module (ingestion, chunking, retrieval, API routes, frontend) stays
exactly the same — that modularity was a deliberate design goal so the
prototype could evolve into the firm-wide deployment without a rewrite.
